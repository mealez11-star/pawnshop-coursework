# Информационная система для ломбарда

Курсовой проект Сокольникова для первого курса Московского Политеха.

Программа написана на Java 17 и работает с MySQL через чистый JDBC. Графический интерфейс сделан на Swing: JavaFX в задании указан как рекомендуемый, а не обязательный. ORM-библиотеки не используются.

## Что реализовано

- MVC: пакеты `model`, `view`, `controller` разделены.
- JDBC-подключение сделано по шаблону Singleton.
- Все запросы параметрические (`PreparedStatement`).
- Регистрация и авторизация.
- Проверка сложности пароля регулярным выражением.
- Хранение не пароля, а PBKDF2-хеша с индивидуальной солью.
- Роли `ADMIN` и `USER`.
- Администратор управляет пользователями, клиентами, договорами, товарами, ценами, продажами и составом договора.
- Один и тот же товар можно закладывать многократно: после возврата клиенту
  он добавляется в новый договор и снова получает статус «В залоге».
  Одновременно держать товар в двух действующих договорах нельзя.
- Оценочная стоимость задаётся отдельно в каждом договоре. Поэтому один и тот
  же товар при повторных залогах может иметь разные оценки.
- Новые цены и продажи можно оформлять только для товара со статусом
  «Собственность ломбарда»; возвращённые, заложенные и проданные товары
  не показываются в списках создания операций.
- Товар можно перевести в собственность ломбарда только после истечения
  срока возврата по его текущему договору. Старые договоры остаются историей
  и не влияют на срок нового залога. Например, при сроке `2026-09-17`
  переход, назначение цены и продажа разрешены с `2026-09-18`.
- Досрочный возврат товара клиенту разрешён, а статус «Продан» программа
  устанавливает только автоматически при создании продажи.
- В одном договоре каждый товар обрабатывается отдельно: часть залогов можно
  вернуть клиенту, а часть после срока передать ломбарду.
- Цена товара хранится как история по датам и может как уменьшаться, так и
  увеличиваться. Цена, уже использованная в продаже, не изменяется задним числом.
- После возврата, передачи товара ломбарду или повторного залога старый договор
  и его состав доступны только для просмотра.
- Поля дат имеют явный формат `ГГГГ-ММ-ДД` и получают удобные начальные
  значения: сегодня, срок возврата через 30 дней и текущий месяц для отчёта.
  Перед сохранением любую дату можно изменить вручную.
- Обычный пользователь видит и изменяет профиль, а также видит только собственные договоры и залоги.
- Финансовый отчёт за выбранный период.
- Транзакции при регистрации, изменении профиля и продаже товара.
- Внешние ключи, уникальные ограничения и `CHECK`-ограничения целостности.
- Сборка исполняемого JAR вместе с JDBC-драйвером.

## Соответствие реляционной модели

| Отношение из модели | Таблица MySQL | Класс Java |
|---|---|---|
| Пользователи | `users` | `User` |
| Клиенты | `clients` | `Client` |
| Договоры | `contracts` | `Contract` |
| Состав_Договора | `contract_items` | `ContractItem` |
| Товары | `items` | `Item` |
| Цены | `prices` | `Price` |
| Продажи | `sales` | `Sale` |

`ContractSummary` и `FinancialReportRow` - отдельные классы-модели для результатов составных SQL-запросов. Это ручная реализация ORM-подхода, которого требует задание.

## Структура MVC

```text
src/main/java/ru/mospolytech/pawnshop/
├── model/       классы объектов предметной области и результатов запросов
├── view/        окна, панели, таблицы и поля интерфейса
├── controller/  обработка действий пользователя
├── dao/         SQL-запросы и преобразование ResultSet в объекты Model
├── config/      Singleton-подключение к MySQL
├── util/        проверка данных и хеширование паролей
└── Main.java    точка входа
```

DAO находится рядом со слоем Model и отвечает только за сохранение и чтение моделей. В классах View нет SQL, а в DAO нет элементов Swing.

## Первый запуск

Нужно установить:

1. JDK 17 или новее.
2. MySQL Server 8.
3. IntelliJ IDEA с поддержкой Maven.

Далее:

1. Открыть MySQL Workbench.
2. Выполнить файл `database/schema.sql` целиком.
3. Открыть папку проекта в IntelliJ IDEA как Maven-проект.
4. Если у пользователя `root` есть пароль, изменить `src/main/resources/db.properties`:

```properties
db.url=jdbc:mysql://localhost:3306/pawnshop?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Europe/Moscow
db.user=root
db.password=ВАШ_ПАРОЛЬ_MYSQL
```

Можно не менять файл в ресурсах, а создать рядом с JAR отдельный `db.properties` с теми же тремя настройками.

5. Запустить класс `ru.mospolytech.pawnshop.Main`.

При первом запуске создаётся администратор:

- логин: `admin`
- пароль: `Admin@123`

После первого входа пароль следует изменить на вкладке «Профиль».

## Как получить исполняемый JAR

Готовая сборка уже находится в папке `release`. На Windows можно запустить `release/run.bat`. Если у MySQL-пользователя `root` установлен пароль, сначала переименуйте `release/db.properties.example` в `release/db.properties` и укажите пароль.

JAR в папке `release` использует единственную внешнюю библиотеку — официальный
JDBC-драйвер `release/lib/mysql-connector-j-8.4.0.jar`. Повреждённая и не нужная
для обычного JDBC библиотека Protobuf из комплекта удалена.

Для самостоятельной пересборки в терминале из корня проекта выполните:

```bash
mvn clean package
```

Готовый файл появится здесь:

```text
target/pawnshop-app.jar
```

Запуск:

```bash
java -jar target/pawnshop-app.jar
```

Плагин Maven Shade помещает JDBC-драйвер внутрь JAR, поэтому отдельно копировать драйвер не нужно.

## Демонстрационный сценарий для защиты

1. На окне входа зарегистрировать клиента. Показать, что слабый пароль отклоняется.
2. Войти как `admin`.
3. Создать товар со статусом «В залоге».
4. Создать договор для зарегистрированного клиента.
5. Открыть «Состав договора» и добавить товар с оценочной стоимостью.
6. Для демонстрации повторного залога вернуть товар клиенту, создать новый
   договор и добавить тот же товар с другой оценочной стоимостью.
7. После истечения срока текущего договора изменить статус товара на
   «Собственность ломбарда».
8. Добавить несколько цен: одну ниже предыдущей и одну выше, показав, что
   цена может изменяться в обе стороны.
9. Создать продажу. Статус товара автоматически станет «Продан».
10. Построить финансовый отчёт.
11. Выйти и войти как обычный клиент: ему будут доступны только профиль и его договоры.

## Где показать требования преподавателя

- Singleton: `config/DatabaseConnection.java`.
- Параметрические запросы: все классы в `dao`.
- Хеширование: `util/PasswordUtils.java`.
- Регулярное выражение пароля: поле `STRONG_PASSWORD` в `PasswordUtils`.
- Ролевая модель: `model/Role.java`, `view/MainView.java`, проверки в `MainController`.
- Результат запроса как объект: `ContractSummary`, `FinancialReportRow`, `ReportDao`.
- Транзакции: `UserDao#createRegularUser`, `UserDao#updateProfile`, `SaleDao`.
- Целостность: `database/schema.sql`.

## Важное ограничение

Удалить клиента или товар, на который ссылается действующий договор, MySQL не позволит. Это не ошибка программы, а защита ссылочной целостности. Сначала нужно удалить или изменить зависимые записи.
